# 小小情自主开发实施计划与验收清单

确认日期：2026-11-03，北京时间。版本：需求基线 1.0。

本计划按[方案书](autonomous-evolution-design.md)实现自主配置调整、自主开发、知识成长和全局费用治理。各阶段必须给出源码、检查结果、运行版本、恢复入口和明确的完成范围，完成后再更新下方状态。

当前状态：用户已授权开发；P0 源码基线已整理，P1—P6 已实现主要代码并完成下述隔离回归，P7 生产闭环尚未完成。持久发布器和生产覆盖层未启用，源码未推送。具体证据、限制和启用步骤见[实施记录](autonomous-evolution-implementation.md)。既有桌宠能力只计回归，不算本计划新增。

## 1 实施顺序与交付原则

先整理受控源码和真实费用归属，再建立唯一身份、审批和隔离执行；随后接入统一配置、知识库和开发任务闭环，最后完成生产与 Windows 联调。已有日程、能力目录、扩展协议和回执优先复用。

每个阶段按独立变更提交，使用明确路径暂存，不提交账户、数据库、聊天、媒体、实际环境配置或生成安装包。保持两个仓库各自历史；推送、合并、部署和 Releases 分别执行。

普通低风险代码检查不反复扩大测试范围；涉及消息入口、身份、热重载、配置生效和发布时必须执行相应真实框架回归。测试失败时修复并补充能复现根因的检查，不能靠关闭测试通过。

## 2 P0 源码基线与接口盘点

**目标：让后续自主修改可追踪、可重现、可恢复。**

- 盘点父仓库、Coopanion 子仓库、AstrBot 镜像、受控覆盖层和运行插件的版本及来源。
- 将需要维护的陪伴、记忆、表情与 OAuth 接入源码整理成明确的受控源码或补丁；保留私有配置和数据的排除规则。
- 记录现有配置写入、角色贴合调参、活动目录、扩展注册、工具发现、Token 统计和发布恢复接口，确定复用点。
- 列出已有 B 站阅读、资料柜等接口与实际后端的差距，避免重复开发。
- 准备专用测试数据、两个 Bot 的隔离身份和可重现的框架测试环境。

交付：源码与补丁清单、兼容版本、迁移映射、敏感目录规则、现有功能基线和恢复演练记录。

完成条件：从受控提交与指定依赖可以准备测试环境；私有数据未进入 Git；生产源码漂移可被检测；恢复不需要启动旧 HAPI、cc-connect 或共用 OAuth 刷新进程。

## 3 P1 全局用量账本与预算入口

**目标：在新增自主消耗前，看清全部请求的实际归属和成本。**

- 在提供商请求入口和用量返回处统一追踪，覆盖直接调用、流式请求、重试与错误结果。
- 使用请求标识、任务标识与上下文传递记录发起插件、功能、Bot、人格、模型和 effort。
- 统一存储实际、估算、缺失和待结算用量，处理缓存、推理、向量化等计费字段。
- 建立价格版本、2500 美元月度配置基准、子预算和并发预占结算。
- 接入现有账户用量读取；提供独立的项目预算和账户报告视图，未知字段不换算成确定余额。
- 在数据与日志加入费用页面，先完成汇总、筛选和明细，再增加图表及更新通知。
- 兼容原有自主活动日 Token 上限，明确多个上限同时存在时以最先触达者停止新请求，不另建可绕过的调用通路。

完成条件：同一物理请求只入账一次；多插件上下文不重复计费；失败重试仍可归属；并发请求共享预占；开发关闭后统计仍运行；没有数据时显示未知。

## 4 P2 唯一主 Bot 与治理基础

**目标：先完成权限和恢复，再开放修改能力。**

- 固定小小情的已验证 Bot、平台和人格绑定，全项目只接受一个自主开发主 Bot。
- 对任务创建、恢复、工具调用、配置写入、提交、推送和部署分别核验身份。
- 验证陪伴和记忆依赖、接口版本与当前人格可用性；依赖关闭时保存断点并暂停。
- 实现三种开发审批模式、重大变更分类、版本绑定审批、撤销和过期处理。
- 建立隔离工程环境，验证路径、链接、子进程、临时目录和私有数据边界。
- 建立全局修改与部署锁、人工维护优先级、独立发布入口和紧急停用恢复入口。
- 注册开发模型与 effort 配置，复用 AstrBot 提供商和单一 OAuth 刷新所有者。

完成条件：初小晴、其他用户、名称伪装、引用确认和跨端身份伪造均不能授权；过期审批不能执行；工作区外修改被实际阻止；治理模块失效时暂停执行，不自动放行。

## 5 P3 统一配置与能力管理

**目标：兑现既有配置自调授权，保持所有入口一致。**

- 提供独立的自主配置权限，迁移之前明确授权的范围，不与开发模式捆绑。
- 统一面板、聊天、角色贴合调节、自主任务和配置迁移的保存接口。
- 为已接入插件登记字段范围、类型、人格、依赖、生效方式和撤销规则。
- 实现人工锁定、版本冲突检查、实际有效值、调整观察期和恢复。
- 阻止跨人格继承影响和受保护字段的自主修改。
- 汇合功能自知、陪伴活动、扩展注册和桌宠能力状态；兼容已有完整活动标识。
- 将原手填活动名单改成可读的授权列表，保留没有待处理任务时的正常不可用原因。

完成条件：同一值不会被两套调参机制争抢；人工新修改不被旧任务覆盖；初小晴配置不变；关闭开发后既有配置权限和记忆、表情活动保持应有行为。

## 6 P4 知识库自主维护

**目标：真实保存、索引和使用有价值的信息。**

- 增加陪伴面板中的自主维护开关、可读库与可写库、主题、来源和费用限制。
- 提供创建小小情学习库的流程，明确初小晴与公共资料的隔离和共享选择。
- 实现候选、正文获取、价值判断、来源记录、去重、版本更新、入库、索引确认和检索回查。
- 单独核验 Embedding 与可选重排模型，登记提供商和计价；不能假定聊天 OAuth 自带索引服务。
- 接入自主日程和用量账本，长任务有断点、超时和重试上限。
- 将学习动机与成果摘要关联记忆、日记和兴趣目标，保留资料来源与可信度。
- 验证网页、Skill、QQ 私有内容、视频内容和工程日志不能绕过权限或混入错误资料范围。

完成条件：空库有明确提示；重复抓取不重复入库；索引失败不声称已经可检索；更正可追溯；未授权库不可写；实际问题可以检索到保存的资料。

## 7 P5 自主开发闭环

**目标：从一个实际需要走到可验证的新能力。**

- 按目标编号管理需求、兴趣、缺失能力和反馈，合并重复事项并关联既有未完话头。
- 优先评估已有插件和适配器，生成可审核方案、影响范围及费用上限。
- 按审批模式执行隔离修改、工具调用、测试与差异审查；审批前只能进行允许的调研和草案生成。
- 实现任务断点、有限自修复、人工维护互斥和聊天优先；工程执行不占用真实聊天会话锁。
- 提交父仓库或子仓库任务分支，通过受控入口上传，保存实际提交与检查结果。
- 发布后登记能力、配置、权限、用量和执行回执，再由陪伴日程决定实际使用与分享。
- 模型选择与回执核验分别执行，不能用“我测试过了”等自然语言代替证据。

完成条件：完成一次范围明确、可恢复的低风险功能变更，经历方案、修改、测试、提交、部署、能力登记与实际使用。失败和取消路径也保留正确状态，不能成为无限循环。

## 8 P6 发布恢复与 Windows 联调

**目标：更新不破坏原有聊天、账号与客户端。**

- 在隔离环境完成补丁兼容、生产更新预检和独立回滚演练。
- 针对公共核心、消息、身份和存储改动执行双 Bot 必需回归。
- 验证正在回复时更新、更新后同会话继续聊天、发送与引用包装幂等、未知投递不重发。
- 对客户端改动构建 Windows 安装包，验证原 UI、配对保留、协议兼容、断线重连、升级与回退。
- 验证 QQ 与桌宠来源、主动路由、图片与 GIF、原生授权、隐藏和手动免打扰的区别。
- 记录代码已上传、服务端已部署、客户端已安装和自然体验确认各自状态。

完成条件：两个普通 QQ 回复通路保持正常；桌宠升级保留配对；失败能恢复且不回滚新增聊天；测试不自动向 QQ 好友或群发信。

## 9 P7 端到端验收与启用

首个完整扩展案例以 B 站阅读能力为目标，先评估已有接口是否可补接。案例应取得有意义的实际内容，保留来源，写入已授权资料库，形成可追溯学习成果，再由人格选择是否与你分享。若需要登录，由你提供专用账号并完成必要登录；未获账号时分别验收公开阅读与登录依赖状态，不冒用现有账号。

另完成一次已授权的配置自调，证明它不必启动完整开发模型；完成一次拒绝或撤销审批、一次恢复任务和一次发布失败回退。涉及 Windows 或外部公开操作的验收单独标记人工步骤，不能用模拟测试冒充。

完成后在小小情范围启用所选模式，初小晴继续无开发权限。真实周期内观察费用、任务价值、重复任务、消息延迟与故障；观察时长和上线数值由最终验收确定，不预先填写成功结论。

## 11 必需回归范围

| 功能 | 必需场景 |
| --- | --- |
| 消息与热重载 | 两个普通回复路径、在途更新、后续同会话、取消与异常释放、发送包装幂等、引用有效性 |
| 工具调度 | 真实 FunctionToolExecutor、实际人格解析返回结构、普通输入与查询共用鉴权 |
| 戳一戳与跨端 | 自己和对方的方向、最近上下文、桌宠触摸与 QQ 戳动区分、主动终端选择 |
| 图片与表情 | 静态和 GIF、稳定图片 ID、收录与暂存、重复识别、人物确认、两端媒体目标 |
| 用户与记忆 | 称呼、专属关系、画像证据、习惯阈值、话头去重与结案、日记来源、人格隔离 |
| QQ 空间 | 独立原生账号、后台访问、关注与浏览去重、点赞评论真实回执、不盲目重试 |
| 日程与提醒 | 全日计划、动态推迟、真实执行时间、提醒独立运行、开发暂停与免打扰 |
| 插件与模型 | 装载卸载、依赖缺失、补丁漂移、OAuth 单一刷新、模型不可用与明确备用策略 |
| 桌宠与 Windows | 原 UI、身份只读、QQ 头像、消息时间、气泡图片、隐藏恢复、电源状态、配对及原生授权 |
| 费用与恢复 | 多种调用归属、并发上限、价格缺失、账户接口异常、历史未知、紧急停用和代码恢复 |

修改发送、入口、引用或执行热重载时，必须运行 tests/test_send_tracking_hot_reload.py，并验证两个 Bot 的普通回复通路。优先使用项目已有真实框架回归；文件名和调用方式按 P0 确认的环境执行。

## 12 上线前仍需确定的参数

| 项目 | 当前约定与处理 |
| --- | --- |
| 2500 美元来源 | 待确认是账户额度还是人工项目预算；数据结构同时支持两者，未核实前不展示确定的真实余额 |
| 月账期 | 可配置起止与重置时间；界面按北京时间显示，不擅自认定账户每月一日重置 |
| 开发日限额与单任务限额 | 在费用基线可观测后配置，不能因已有月额度就默认允许单任务用完 |
| 告警和预留比例 | 配置化并在验收时确认，保护正常聊天，不写死未经确认的数值 |
| 可自主配置字段 | 先接入当前有明确授权的范围，展示字段与影响；新增或保护项按规则处理 |
| 首次启用模式 | 首次默认“每次询问”，四活动授权默认开启但可关闭；保留后续显式设置；生产尚未启用 |
| B 站专用账号 | 用户后续提供或登录；未提供时只验证无需账号的范围 |
| 知识库索引模型 | 待核验或配置向量化及可选重排服务与单价；依赖缺失时暂停索引，不声明完整入库成功 |
| 生产和 Windows 发布策略 | 根据改动影响与审批配置执行；正式签名、自动升级不作为默认已具备能力 |

这些参数不阻碍先整理源码、设计接口和编写隔离回归；在依赖该参数的付费执行、对外操作或生产启用前必须核实。
