# `user_memory.py` / `contact_boundary.py`：主动联系误停修复

2026-11-11，北京时间。涉及 `vendor/installed-plugins/astrbot_plugin_private_companion/`，未修改桌宠客户端或 QQ 登录实例。

## 原因

小小情的主动调度仍在执行，主要用户的主动权限开启，未回应计数为 0。最后一次主动发送发生在 11 月 9 日 11:05。当天 11:31 的措辞纠正含有“以后……不要再说某个词”，旧规则只凭“以后/不要”就判断为持续边界，写入无到期时间的 `contact_preference=no_contact`。后续普通聊天保留了这个标记，互动状态持续为 `avoidant`，从而把有效主动额度压到 0。

旧诊断只报告“每日上限为 0”，同时列出配置值 5，未说明真正的联系边界。当前高主动预设的有效上限为 15；配置原值与预设均未因本次修复改变。初小晴修复前后的有效额度一直为 15。

## 修改

- `contact_boundary.py` 仅识别明确停止联系、打扰、交谈或发消息的请求，排除引用、举例、否定转述及针对词语、称呼、戳一戳、特定消息形式的偏好。
- `user_memory.py` 的持续联系边界判定使用上述规则。普通措辞纠正继续进入既有偏好/对话流程，不会关闭全部主动联系。明确要求停止联系仍写入边界，普通闲聊不会自动解除。
- `proactive.py` 在配置没有关闭时，将联系边界或互动状态导致的暂停写成相应诊断原因。

通过已鉴权的管理接口，仅纠正主要用户经原聊天核验的错误联系标记。用于纠正的手工互动投影立即到期，不留下长期手工关系覆盖。关系分数、角色、记忆与用户权限均保留。调度器随后自动取消过期的旧空间分享计划并安排后续任务，没有强制发送 QQ 测试消息。

## 验证与部署

隔离、无网络的实际 AstrBot 镜像中，89 项测试及 2 个子测试通过，覆盖两个人格的真实意图判定、互动结算、每日额度、明确禁联保留、关系策略与重载期间普通回复。另一个旧模型路由用例的替身缺少新接口，与本次修改无关，未纳入本次验收。旧测试的独立模块导入方式通过预先加载实际人格配置包进行兼容，没有替换实际判定函数。

线上源文件、版本管理源码与 `overrides/evolution-source-baseline.json` 的三个文件摘要一致。已通过管理 API 重载陪伴插件；两个 QQ 账号自动绑定正常。重新读取两个用户及两套有效配置，确认配置完全相同、关系分数和权限不变，小小情有效额度恢复为 15，初小晴维持 15。有效周期心跳继续更新，主要用户的新计划处于未来时段。

源码和状态备份、测试日志、部署记录及核验结果保存在忽略目录 `.runtime/proactive-contact-20261111/`。原始聊天、用户状态和管理凭据不提交。实际下一次消息是否送达，应以后续正常调度的发送回执为准，本次未人为触发测试聊天。
