# 主要用户机制讨论开关与开发审批通知（2026-11-18）

## 原因

自主开发已产生真实方案并进入待审，但 16:56 的主动候选被标为 `blocked`，原因是“内部机制泄露”。此前只确认 `offered=true`，它代表候选入队，不代表消息已经生成或发送。

用户明确授权小小情向其主要用户讨论自身机制，并要求做成可按 Bot 控制的开关。因此不关闭整体审核，不用改写术语的办法掩盖真实开发事项，而是将授权接入候选、人格判定、生成、改写和最终发送。

## 行为与配置

- 陪伴面板“配置 → 私聊陪伴”新增“向主要用户说明内部机制”，键为 `allow_owner_internal_discussion`。默认关闭；本次仅为小小情开启。
- 每个人格独立保存，配置版本 18 为已有副人格物化 `false`，避免继承主人格后意外开放。初小晴保持停用，其开关保持关闭。
- 开关开启时，仍须核对主要用户身份、当前 Bot 平台绑定以及一对一会话；仅给用户记录打一个 `owner` 标签不能取得许可。群聊、其他用户和其他人格保持原规则。
- 允许自然说明自身模型、插件、记忆、工具、配置、真实错误和开发方案；不再仅凭这些词语把申请误判为泄露。人格、生成及复核提示同步说明这项授权；判定缓存包含开关状态。
- 文字经工具代发或由框架捕获时，也携带经过验证的收件人作用域。既有秘密字段脱敏、事实核对、阶段审批和消息过滤继续生效；工具协议封套不冒充自然聊天。
- 自主开发插件 0.2.3 在该授权新开启后，仅对仍有效、且先前仅因内部机制被拦截的审批通知重新入队一次。旧阻断记录保留；已处理、过期或被取消的审批不会复活，不会替用户批准改动。

## 验证与现场

新增回归覆盖开关关闭/开启、主要用户校验、群聊与另一人格拒绝、候选语义、人格判定提示、解释错误的改写/最终发送、工具代发捕获、配置作用域及默认值；审批通知覆盖策略变化后的单次恢复和撤销。

隔离测试使用实际 AstrBot 镜像，关闭网络，不挂生产聊天或账号数据。宿主隔离专项需宿主执行器，本次正常服务端回归不在测试容器内重跑。旧版 UI 归属测试存在两项既有失败：旧模拟日程字段归属及保存清单已经与当前自主生活 UI 不一致；已用修改前的实际源码复现相同两项失败，本次开关没有新增这两项差异。

详细测试日志、上线前源码/配置回滚材料及最终投递状态保存在排除版本管理的 `.runtime/owner-transparency-20261118/`。验收以真实通知的投递回执、主动档案及聊天历史为准，不能再用候选入队作为发送完成的证据。
