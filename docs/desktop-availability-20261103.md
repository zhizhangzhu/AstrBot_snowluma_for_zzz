# 桌宠可见性、日程时段与消息时间修复

日期：2026-11-03，北京时间。服务端 0.2.4；客户端新增功能进入 0.3.3。Windows 实机升级结果以[验收清单](desktop-pet-acceptance.md)为准。

## 核对结果

- 截图里的早安工具回执在恢复连接后的 10:17 确认，并非已证明在夜间送达。旧路由确实把锁屏、休眠和隐藏写入持久“等待”标记，断网后仍可能压住 QQ 主动交流。
- 两条时段不符的文字来自 AstrBot 的桌宠自主日程模型，均有客户端完成回执；不是客户端自带随机台词。原定 14:30、21:30 的活动在 10:19 执行。动态日程把“延期”计算为“当前时间加几分钟”，没有保留原定未来时段。
- 这个工具发言入口没有明确的执行时钟，并且没有经过普通回复的公共文字清理，所以可能保留句末句号。句号的存在本身不能判断文字是否由 AstrBot 生成。

## 当前行为

| 条件 | 新主动交流目标 |
| --- | --- |
| 客户端可达、身体可见、屏幕可用 | 优先桌宠 |
| 断网、退出、心跳过期 | QQ；应用心跳最长 45 秒失效 |
| 锁屏、休眠、合盖、熄屏或身体隐藏 | QQ；正常恢复后重新报告当前状态 |
| 明确手动免打扰 | 继续等待，两端均不绕过 |

服务端检查应用心跳和状态时效，并在新主动内容提交前等待一次 WebSocket 控制帧往返，最长 2 秒；刚失联但旧心跳尚未过期时，也不会把新内容直接交给失联连接。这不调用模型，也不产生可见聊天。客户端报告 Windows 会话显示电源和盖子状态，并在恢复、重连时刷新。此处采用 Windows 的 [RegisterPowerSettingNotification](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerpowersettingnotification) 与 [Power Setting GUIDs](https://learn.microsoft.com/en-us/windows/win32/power/power-setting-guids)，不通过截屏推测用户是否在看电脑。

已经提交但回执未知的旧消息保留 unknown，不因切回 QQ 而再次发送。只有明确尚未提交的主动消息，才能在提交前失去桌宠时改选 QQ。普通被动回复仍保持原始输入端，表情发送失败不自行转 QQ。

动态日程延期只能推迟，不能提前原定未来安排。桌宠活动的模型输入包含执行时的真实时钟；所有桌宠 say/ask 发言在绑定人格内应用已有公共清理规则，不增加文案重写模型。

聊天在用户消息、Bot 发言、问话、身体互动上方显示原始事件的日期与时间，时区来自 AstrBot 身份；悬停显示秒与时区。无有效历史时间时不编造时间。

## 回归与恢复

覆盖断线、旧等待标记、两个人格、熄屏、静默连接、恢复心跳、发送前切端、未知回执不重发、跨重载普通聊天、真实工具调度、未来日程不被提前、日期跨天和原始消息时间。测试不主动向 QQ 好友或群发送消息，也未锁定或休眠用户电脑。

本地服务端与认知检查 66 项通过、3 项因缺少本地 AstrBot 依赖跳过；实际 AstrBot 镜像中相关框架及日程回归 107 项通过。客户端 515 项通过，World 204 项通过、3 项跳过，三项类型检查通过。Windows 安装包及原生界面验收见[运行记录](https://github.com/zhizhangzhu/Coopanion/actions/runs/41569089049)。

源码增量及哈希位于 `overrides/desktop-availability/`。在线修改前备份位于忽略目录 `backups/desktop-availability-20261103/`；日程修复保留数据库快照与逐项变更记录。已执行活动和原始聊天不删除、不改写。

临时维护通道还修复了重复启动问题：先检查存活服务，才创建新凭据；已退出进程留下的 Unix socket 可以恢复，重复启动不会覆盖现有凭据或删除活跃连接。
