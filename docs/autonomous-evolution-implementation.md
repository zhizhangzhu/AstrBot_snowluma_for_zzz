## 权限边界与网络替代方案

工程代码运行于无网络的一次性容器，源码只读挂入后复制到容器临时目录；回传只接受获准路径的有限文本文件。宿主机发布器只提供登记的源文件发布、固定 AstrBot 重启、任务分支上传和 Windows 构建操作，不执行模型提供的宿主机命令。发布器本身冻结并校验，模型修改其受控源码不会自行替换正在授权的控制器。

公开调研通过独立的有界读取入口。普通直连不可用时仅接受本项目已经使用的固定网关 `proxy.esl.cisco.com:80`；连接和 CONNECT 的目标仍为已验证的公网 IP，TLS 验证原始域名。`trust_env` 保持关闭；不采用任意环境代理，不访问回环、内网、Unix 服务，不转发 QQ 号、聊天、会话 Cookie 或项目密钥。每次跳转重新校验。

用户明确授权生产上线，随后同意将受限发布器注册为 root 系统服务，要求跟随 AstrBot 项目启停、异常退出后自动重启，不独立开机启动。已通过 `systemctl link` 注册 `deploy/systemd/astrbot-evolution-publisher.service` 并启动；没有执行 enable，模板没有 Install/启动目标，WantedBy 为空。`start.sh` 启动项目时启动发布器，`stop.sh` 先结束发布器的在途操作，再最终停止 AstrBot 和 QQ，避免发布操作反向拉起已停止的服务。发布器执行自身 AstrBot 更新时保持独立运行。网络部分采用已验证的固定网关读取实现。

## 启用和回退

已按明确上线授权执行 `prepare`、`apply`，并只重建 `astrbot` 服务。以下为受控部署流程；重做生产切换仍需对应授权：

1. 再核验镜像、源码摘要和未完成的人工改动，记录当前 AstrBot 容器与页面基线。
2. `python3 scripts/evolution_deploy.py apply` 启动私有固定发布器并创建 opt-in 标记。
3. 通过 `scripts/common.sh` 中的 `compose` 函数仅重建 `astrbot` 服务，使用 `up -d --no-deps --force-recreate astrbot`；不要对整个栈执行 down 或重启两个 QQ 实例。
4. 登录 6185 检查原页面、新页面、单一 OAuth、双 Bot 连接与依赖；验证读接口后，开展一次经过批准的真实低风险任务。未经额外授权不向好友或群发送测试消息。
5. 记录线上提交、模式、实际模型、估算费用和检查回执。生产巡检与自然体验结果追加记录，不改写旧聊天来补证据。

紧急停用：`python3 scripts/evolution_deploy.py disable` 先移除标记并停发布器，再通过同一 Compose 管理入口仅重建 AstrBot，移除本轮覆盖层。账本、配置、聊天、知识和任务数据保留。原陪伴/桌宠运行数据不会恢复成旧快照。

需要更新宿主发布器时必须人工重新准备与校验；不能让工程任务自行刷新固定控制器。部署已发生的代码变更可由任务的单独回滚入口恢复；若文件已被人工再次修改，或已有依赖该版本的后续源码基线，则停止覆盖。回滚最近发布同时恢复该任务的源码基线，不回退其他仓库记录。

## Windows 部署约定

小小情可以维护、检查、提交客户端源码，父仓库单独固定子模块。不在线的 Windows 终端不影响这些开发步骤。

客户端代码经授权上传后，固定 CI 必须对精确提交报告原 UI、WSS 配对、消息/图片/GIF、气泡显示回执、头像、时间、电源观察、隐藏恢复和重装保留配对均通过，才生成具体版本、SHA、构建编号、到期时间和一次性 nonce。没有报告或报告失败不安装。

用户在面板复制该版本的 PowerShell 指令，运行 `scripts/windows/Start-AstrBotDesktopUpdate.ps1`。这个通道只获取 manifest 与对应安装包、验证 SHA、更新选定安装位置并传回版本回执；不是把通用维护终端交给 Bot。它保留 AppData 中配对/聊天，失败恢复安装目录。过期或失败后可在已批准任务中人工续期，旧 nonce 失效；再次安装仍要用户运行指令。

安装结果只说明安装器和实际包版本已核验，不能替代启动后的联网和自然使用验收。该新增脚本需要后续 Windows 实机验证；本轮没有要求用户开放通道。

## 知识库能力认知及服务托管核验（2026-11-04）

普通聊天的模型请求现在附带实时知识能力状态：维护开关、实际可用向量服务、所选可读／可写库，以及未就绪原因；初小晴请求不会注入小小情的能力状态。模型可使用 `autonomous_growth` 的 `knowledge_search`、`knowledge_save`、`research` 操作。已取消和终结的开发目标不再作为待办提示。

生产快照确认：维护开关开启，Embedding 提供商 0 个，现有知识库 0 个，知识入库 ready=false，原因同时包括缺少向量化服务和可写库。这意味着功能已经实现，但当前不能声称自主入库已在自然日程中发生。读取公开资料可形成候选；真正写入须通过来源正文核对、长期价值判断、去重、授权和日限额，再由原生知识库切分／索引，并检索回查确认。聊天记忆不等于该资料库。

配置顺序：

1. 在 AstrBot“模型提供商 → 嵌入”配置实际可用的 Embedding 服务；费用治理中补充对应模型价格，不能以未知单价绕过预算。
2. 在“自主成长 → 知识”选择服务，创建“小小情学习库”；此入口会登记小小情的读写及归属范围，默认不向初小晴共享。
