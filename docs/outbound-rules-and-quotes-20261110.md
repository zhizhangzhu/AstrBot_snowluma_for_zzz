# 聊天统一发送规则与按需引用（2026-11-10）

## 核对结论

此前并非所有出口都符合统一规则。戳一戳直接发送，11 月 10 日第一次修复只补了句尾句号；桌宠平台能力表明确将 `segmented_reply` 设为 false，且 `terminal_output` 另有直接展示模型原文的通知通道。私聊引用工具曾成功选中候选，但发送前本地相关性检查要求旧消息同时匹配当前输入、第一段输出的字面词，阻碍回到旧话题和分段回答。默认只有最近 12 条候选，较早话题难以被选中。

## 统一规则入口

`outbound_rules.plan/send_event` 复用当前人格配置的既有分段器，不创建另一套正则。事件路径使用 `_segment_llm_reply_chain`，后台路径使用同源 `_split_llm_controlled_text_for_event` / `_split_proactive_text` 与组件规划器。保持正文替换、段尾清理、完整语义控制标记、保护代码/网址/引文、媒体位置、发送间隔等配置；最终出口另校验敏感信息脱敏与违禁词。组件上的处理标记防止重复分段；实际成功片段才进入发送账本。部分失败立即停止，不整条重试，桌宠投递结果不明时不降级到 QQ。

| 出口 | 处理位置 |
| --- | --- |
| QQ/桌宠普通最终回复、同事件工具/图片补发 | 最终发送追踪包装；已有 decorating 计划标记为已处理 |
| 戳一戳/反戳配文 | 同一网关；在规划前保留语义边界，记录确认送达的片段和图片 |
| 后台主动消息、精确平台发送和 OneBot 兜底 | `_send_chain_components` 在装饰前后校验与规划，随后沿原路投递 |
| 其他插件、原生发送工具的 `Context.send_message` | 既有 QQ 历史桥中按真实 Bot/人格作用域规划，再发送和记录 |
| 桌宠额外的说话工具、收图询问等主动消息 | 服务端统一规划后投递；删除原文显示旁路，保留费用通知 |
| 转述工具、兼容的外部主动聊天桥 | 优先委托统一发送入口；后者当前未安装外部插件，不额外启用 |
| OneBot/桌宠流式回退 | 收齐 MessageChain 增量后走统一入口，不使用适配器自己的句读正则 |

两个 Bot 当前均关闭 `streaming_response`；新增流式回归覆盖将来开启后的受控入口。没有更改账号、功能开关、分段内容或时间参数。结构化授权表单（如 pet_ask）维持一个交互，已沿现有 common transforms 清理展示文字。QQ 空间发布属于公开动态，不拆成聊天消息。未宣称能拦截项目外程序绕过 AstrBot 直接调用 QQ 协议接口。

## 引用

- 明确鼓励在补答多条输入中的某一条、纠正、接续较早话题时引用，普通顺畅接话仍按需使用，不设引用概率或固定频次。
- 可用 `pc_private_quote(operation="search", query="关键词")` 在当前账号、人格、会话和有效时间范围中查找较早的原消息；返回本轮不透明 ref，禁止猜 QQ message ID。原有最近候选和时效配置保持不变。
- 对照完整回复核对相关性，第一段只是过渡不再误伤。明确的本地相关性直接通过；仅在选择了引用但字面证据不足时做一次缓存的语义核对，6 秒调用超时、7 秒外层上限，失败保留普通回复但不附不确定引用。
- 保留账户/人格/会话绑定、撤回和可读取性检查；语义核对后再验作用域。仅第一段可见文字附引用，后续段不重复。
- 增加已选择、已发送、未附加原因日志，不记录完整聊天正文。
