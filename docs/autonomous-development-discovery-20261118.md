# 自主开发未产生任务：修复与回归（2026-11-18）

## 故障与原因

生产任务库只有 11 月 3 日的设计连通性验收任务，该任务已取消；11 月 4～12 日的六次目标评估均选择不新增目标。11 月 18 日 15:57，主要用户再次提及自主开发后，模型调用 `autonomous_growth(operation="status")`，因省略无内容的 `arguments` 而在 Python 方法绑定阶段失败，尚未进入鉴权和错误封装。此前测试总是显式传入字典，漏掉了真实调用形式。

后台目标评估另有三处缺口：传入所有旧目标但没有状态，使已取消验收任务的“只规划、不改文件”被误读成后续开发限制；没有明确提供同人格近期对话与执行反馈；完全依赖模型选择评估机会。旧实现还在模型成功返回前标记当日已评估，空结果会被当成“不开发”。审批已有面板入口，但缺少独立主动通知。

## 修复后的行为

- `autonomous_growth` 和 `local_wiki` 的空参数查询可省略 `arguments`。参数仍在身份核验之后按操作校验；缺少写操作必需字段会返回明确失败，不能取得执行、批准或上传权限。
- 开发评估只读取经过账号与人格验证的主要用户共享会话，兼容文本字符串和多模态文本块；工具结果不当作用户请求。只保留有界对话、反馈及同作用域近七天已确认活动摘要，不读取其他人格的聊天。
- 目标列表排除取消、完成等终结任务，其余目标携带 ID 和状态。单项任务的范围不再被表述为所有未来开发的边界。
- 已验证聊天中的开发反馈会去重保存为评估线索，不直接生成补丁或批准任务。新增反馈在空闲日程中安排评估，同一天新反馈最多每小时评估一次；没有新反馈时每天 16:30 后补一个评估机会。实际执行仍遵守陪伴日程、账号状态、预算、空闲和授权限制。
- 只向现有陪伴活动队列入队，并唤醒同一个协调器，避免原主动计时器休眠造成“已入队但不执行”；不新增工程执行循环。已有可推进任务也进入该队列；未批准阶段不会因入队而获得执行权。
- 开发需求是否已处理以自主开发自己的持久化评估结果和任务修订为准。生产核验发现 QQ 状态同步回执可能让一次维护期间未实际执行的日程显示成功；队列会重新接纳没有实际开发结果的工作，不复用已终结活动的去重键，也不把 QQ 状态同步当作工程成果。
- 只在有效模型决定及执行前授权复核通过后记录评估完成。空返回、无效 JSON 或缺少决定字段保留待评估状态，十分钟退避；同日同一批反馈最多三次失败尝试，新反馈或次日才重新获得机会。模型明确判断暂不开发是合法结果，不为验收凑任务。
- 有真实、有效的待审方案时，通过陪伴插件主动候选机制生成符合人格的申请，附实际审批 ID 和阶段；一项审批只入队一次，已处理、过期、撤销或因维护失效的待发候选会取消。走现有消息路由、过滤、免打扰与额度，不用固定问句直发 QQ。
- `status` 查询和管理快照可读取最近评估结果及队列健康状态。仅有排程或文字承诺不能声称完成代码开发。

开发模式保持原配置，主要开发 Bot 仍只允许小小情；未开启自动批准、远程上传或任何宿主权限。初小晴继续暂停。
