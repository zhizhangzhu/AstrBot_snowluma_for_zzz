# 对话、画像与表情认知修复记录

日期：2026-11-02（北京时间）。服务端插件为 0.2.3；客户端新增修复进入 0.3.2，安装状态以[验收清单](desktop-pet-acceptance.md)为准。受控源码、基线与恢复方式见 [补丁说明](../overrides/dialogue-cognition/README.md)。

## 根因与修改

| 现象 | 根因 | 修改 |
| --- | --- | --- |
| 专属关系一直空白 | 旧字段只有手动保存；成长任务不生成该字段，资料筛选又容易遗漏较早的双方关系对话 | 复用成长整理任务，保留当前人格的关系证据与邻近上下文，存储自动关系事实；允许作为正常模式的关系背景，不改评分模式或授权。手动文本优先。 |
| 未完话头重复、完结不更新 | 明文完全相同才去重；片段会反复新增旧任务；反馈词和较早上下文选择不完整 | 增加保守同义合并、模型按当前编号提出合并、状态与证据校验；旧片段不能重开已结案事项。不同具体时间和引用主题不合并。 |
| 习惯栏没有内容 | 生产资料有候选，但覆盖天数不足，界面只显示“采集中” | 保留统计习惯的跨天阈值，显示候选数和覆盖日期；有明确自述的习惯保留原话，问句不当声明。没有制造习惯来填空。 |
| 叙事被当成职业 | 职业规则中的“我当……”匹配了“我当时……” | 排除时间、叙事和非职业描述；真实职业声明仍可抽取。已对用户指出的错误事实执行既有治理抑制，不删除原证据、不猜职业。 |
| 发过图片却只记得占位符 | 图片原件缓存、图包语义和历史正文之间没有稳定标识 | 发送成功后归档 `image:<SHA-256前缀>`、可读语义和认知版本，原件仍按人格/用户/会话隔离；共享历史读取同一正文。无可验证原件时明确说明缺失，不猜图。 |
| 认知不能持续更新 | 历史中的静态文本不能反映后来纠正 | 按图片 ID 查询当前允许图库的语义元数据；人物状态、情绪、原文、含义及版本随元数据修正更新。已确认与模型候选分开，不将每次查询变成新识图请求。 |
| 连续触摸和换装触发多次处理 | 单条事件直接入模型队列 | 桌宠短窗口合并触摸，附最新换装，一轮回应；原始事件编号与投递状态逐项保留。合并内容先持久化，停机待输入恢复；换装本身不逐次唤醒模型。 |

## 使用方式

1. 从陪伴面板选择正确人格，查看用户关系、未完话头和行为习惯。整理按现有后台周期运行，不是每次点击页面就调用模型。
2. 图片发送记录提供稳定 ID。小小情需要确认人物、文字、含义或是否收藏时，使用现有图片状态工具查询该 ID；收录回执与认知是两件事，暂存不等于已入库。
3. 纠正人物和图片语义仍使用现有确认 / 元数据编辑流程。更正元数据后查询即反映新版本；没有可靠身份依据时仍会询问，不保证所有角色都能自动认出。
4. 历史中已经丢失原件对应关系的旧占位符不会被随意配图。新发送记录使用完整标识；能恢复的旧图继续由原件缓存和查询工具读取。

## 验证

覆盖职业叙事误匹配、关系原文证据 / 手动优先 / 人格隔离、同义话头与不同时间、旧任务不重开、事件批次与停机、动态图身份、图片实时语义修订及 QQ 发送字段不含私有认知。

另运行实际 AstrBot 框架的普通消息、跨端回复和生成中热重载回归，以及表情状态、发送、纯表情回复和语义查询回归。没有自动向 QQ 好友或群发送测试消息。后台整理只学习，不代替用户发消息或执行点赞等社交操作。

实际框架回归 112 项通过，包含 4 个子测试；表情模块相关回归 235 项通过。本地服务端与认知检查 55 项通过，3 项因缺少本地 AstrBot 依赖跳过，涉及实际框架的检查另在 AstrBot 镜像中运行。源码覆盖层在临时目录完成应用及回滚，全部基线哈希恢复一致。

已核对自动关系资料在小小情正常关系模式下生效，初小晴未获得这份关系；后台整理合并了重复事项，将持续关系偏好归档，不将未知执行结果误记为成功。所指出的错误职业不再展示。统计习惯继续要求跨天证据，界面显示候选与覆盖日期。

## 客户端 0.3.2

| 现象 | 根因与修改 |
| --- | --- |
| “《”后自动另起气泡 | 实际展示回执包含不支持的动作标记“【梗知识】”；解析器忽略动作但仍生成气泡边界。无有效动作时不再分段；成对标题、引号、括号内的有效动作改为行内动作，正常句间动作仍可分段。 |
| 聊天头像只显示首字 | 从已绑定 Bot 身份取得当前 QQ 头像，经服务端校验、缩放和版本化后同步；服务器缓存 5 分钟，客户端每 30 秒查询身份；失败保留上次有效头像。读取网络头像须接收完整数据流，不能把单个网络分块当成完整图片。 |
| 每次输入都说在等当前步骤 | 客户端把本地待发和服务器已接收混用同一句说明。现在区分“正在发送到 AstrBot”与“已接收，等待处理”，只有实际生成生命周期才改变处理状态。 |
| 身体气泡不显示表情图 | 原版仅在聊天页显示附件。现保留 PNG/GIF 原字节，身体气泡加载成功后才确认展示；失败返回失败回执。 |

客户端本地 512 项检查通过；World 204 项通过、3 项跳过；三项类型检查和界面构建通过。Windows 原生安装与气泡附件验收单独执行，不能用本地测试代替用户电脑升级状态。
