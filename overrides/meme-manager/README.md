补丁修改位于持久化 data/astrbot/plugins/meme_manager/main.py，容器重启后保留。插件升级或重装可能覆盖，应重新检查新版本实现，不能盲目套用旧补丁。

已检查语法、热重载结果、配置与选包规则、工具禁用状态和服务健康；未自动发送 QQ 消息，也未对历史图片发起识别。端到端收集须观察后续真实入站图片及待审核队列。


## 已收集表情的精确检索与人物识别

原因：原生 semantic.enabled=false 且没有嵌入提供商时，search_memes 会被从请求移除；分类模式仍可随机发图，却不能按“橘雪莉 放大镜”定位已入库图片。补丁为存在可用语义记录的绑定图库开放本地 caption/tags 检索，不需要新的 API Key、嵌入服务或图片重建。普通聊天继续使用分类选图；显式检索后复用原插件的本轮候选 ID、选包范围、路径和文件哈希校验及图片投递流程。审核桶和未完成语义记录不参与检索。

本地检索只覆盖已经有描述的图片，不等同于完整向量语义搜索；未语义化的旧图库仍走分类随机选图。禁止因搜索无匹配而宣称整个图库为空。发送是否成功仍以实际投递为准。

人物识别：自动收集和后续离线语义化提示词优先识别人物，再描述动作/道具/情绪/用途。自动收集增加 character_name、character_confidence、character_evidence 结构化判断，确认分数 >=0.9 且有证据才补充规范人名和角色标签；低分或疑似身份不写成已确认人名。模型分数不是准确率保证。未进行全量重新语义化，用户人工编辑的 caption/tags 原字节保留。

`data/astrbot/plugin_data/meme_manager/character_references.json` 保存用户明确确认的人物参照。当前只新增用户确认的“橘雪莉”（别名“雪莉”），引用已入库原图的 entry_id 与 SHA256；不复制或修改原文件。分类时从经过路径和摘要核验的参考图取一帧，与待收集图片帧明确区分；最多附带三个已确认角色参照。未知人物仍依赖模型既有知识，不能保证所有角色都能识别；参考图也不能当成所有新图的默认身份。

自动收集缓存版本已提升，仅对后续分类生效。当前用户自行关闭的人工审核保持关闭，未自动改回开启。

`character-lookup.patch` 保存此次补丁，`character-lookup.json` 保存摘要、备份和只读检索结果。补丁位于持久化插件目录，容器重启后保留，插件升级/重装可能覆盖。回滚时从记录的备份目录恢复 main.py、backend/auto_collect.py、backend/semantic/caption.py，删除新增 backend/semantic/metadata_search.py，并恢复此前的人物参照文件（此前不存在则移除此文件），随后仅重载 meme_manager。保留既有图库和用户数据。

已核对本地检索能命中已收集的 23 帧原 GIF、人物参照可读取、插件加载成功、原配置/选包规则/手工语义未变。未运行测试套件、未主动调用视觉模型、未自动向 QQ 发送测试消息；实际模型选择与 QQ 投递及下一张新图的人物识别仍需观察真实聊天。


## 未知人物的聊天确认与独立待定状态

仅对后续新收集的图片生效。视觉分类新增 character_present，判断是否存在需要命名的虚构人物、作品角色或吉祥物；普通照片、文字图和无具体身份的普通动物不发起人名询问。已经通过表情筛选、但人物为空或低于身份置信度门槛的图，仍保存完整原文件到收集待审箱；即使全局人工审核关闭，也不自动接收这类图片。

人物状态 identity_status 独立于分类审核，不改写 suggested_category 或原 needs_review 的分类含义：pending=人物待确认，deferred=人物已搁置，confirmed=用户已确认，recognized=视觉模型已识别，not_applicable=无需确认人物。待审弹窗和概览显示状态。pending/deferred 图片禁止接收到可用图库，保留待定；可由用户明确丢弃。

后台按原入站消息的适配器路由，向该配置的管理员私聊询问；一次显示一张具体图片并带“待定图#…”标识，原图哈希与图包 ID 用于绑定。不会向群友/普通好友逐一询问，也不会把图片发到外部搜索服务。只有未来真实收集事件才排队询问，不追溯向已有图片发问。

同一图片只问一次。同一管理员同时只保持一张已发问图片；用户不回应不会自动催问。用户的新真实消息会暂停已发问/排队的问题，图片转 deferred。岔开话题、不知道、不认识、不确定或疑问句不会被写成人名；陪伴插件的合成图片事件不当成用户的新回复。待定记录没有到期删除机制，继续保留，受原待审箱容量限制（当前 200 张）。

明确回答时，通过 confirm_meme_character 工具处理。刚问完可以直接说角色名，也可说“这是某某”；搁置后请引用具体原图/询问，或说“待定图#编号的人物是某某”；重新发送同一张原图并明确给出人名时也会尝试按文件摘要绑定。只有一张待定且本轮有明确图片/角色指代时也可自动绑定；多张且无法确定时要求引用具体图。工具验证管理员、会话、当前候选 ID、原文件摘要，且人名必须出现在本轮用户原话中，不能由模型从外观或旧聊天猜填；明确否定、疑问和用户自己的昵称声明不接受。

确认后将人名加入 caption/tags，保留动作、情绪及原文字，并作为一次人工编辑保存；登记本地人物参考图，后续可用于识别。当前人工审核关闭时尝试接收已确认图；若分类仍需复核，仍留分类待定；若人工审核开启，则人名确认后仍待用户审核接收。图包暂忙会保留候选。人物确认已应用后不反复重写该图，保护日后的手工编辑。

持久化状态：data/astrbot/plugin_data/meme_manager/character_confirmations.json；待审原图和 classification 状态在原 auto_collect_inbox 目录。导出或搬迁所有插件数据时需一起保留这些文件。

character-dialogue.patch 保存源码及界面差异，character-dialogue.json 记录备份和摘要。回滚时恢复备份中的 main.py、backend/auto_collect.py、backend/semantic/metadata_search.py、pages/app/semantic/script.js、pages/app/a_manage/script.js，移除新增 backend/character_confirmation.py，再热重载 meme_manager。保留已有待定原图、确认记录及用户语义；升级/重装插件会覆盖源码补丁，需重新审查。

已检查 Python 和浏览器 ES Module 语法、插件热重载、工具注册、原图/手工语义/原配置保持；尚未进行真实 QQ 问答或模型人物确认验证，也未运行测试套件或自动发送 QQ 测试消息。

## 2026-10-27 通用模型直接识别

按用户要求，取消自动收集、普通私聊和显式 inspect_meme_image 工具中的私人参考图附件和人名候选表。识别请求只携带当前原图／GIF 采样帧，明确要求模型利用既有视觉及作品知识，先识别动漫、游戏、动画、虚拟主播形象、吉祥物或经典表情角色的名称与可靠出处，再分析动作、情绪和用途。无需图中文字写出人名或用户先报人物名；未知时仍如实保留未知。真人照片仅描述画面，不凭人脸推断身份。

普通私聊仍保持四行摘要兼容格式，人物名和出处放进“可见内容”，是否当前聊天人格的归属判断独立于人物识别。群聊的三行格式同样允许直接识别虚构角色。旧人物确认记录与手工标签保留作检索和历史证据，不再拼成模型的人名候选或参考图。自动收集缓存版本 v5、私聊摘要语义版本 v8，使旧参考图结果不会被当作新链路的视觉缓存。确认／待定和去重逻辑保留，不自动重写已入库或用户手工语义。

单图语义预览在未单独选择模型时复用自动收集的视觉模型，不依赖启用 Embedding。当前仅配置 codex-oauth-gpt-6-luna，本次未切换供应商或复制 OAuth 凭据；将来选择其他已接入的多模态提供商，可使用原有独立识图模型配置。
